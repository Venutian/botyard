The desktop app starts again, on Windows, macOS and Linux. Everything else is as in 2.10.0: free models that are easier to start on, a bot that says why it cannot answer, and a steadier crew.
New to Botyard? Start with
[Getting started](https://github.com/Venutian/botyard/blob/main/docs/getting-started.md).

## Which file to take

| System | File |
|---|---|
| Windows 10 or 11 | `Botyard-2.10.1-win-x64.exe` |
| macOS on Apple Silicon (M1 and later) | `Botyard-2.10.1-mac-arm64.dmg` |
| macOS on Intel | `Botyard-2.10.1-mac-x64.dmg` |
| Linux | `Botyard-2.10.1-linux-x86_64.AppImage` |
| Debian, Ubuntu | `Botyard-2.10.1-linux-amd64.deb` |
| Android phone | `Botyard-phone-1.14.0-android-arm64.apk` |

`SHA256SUMS.txt` has the checksum of each file.

Bots run on AI tools you install yourself. Start with OpenCode: free models, no account, no card.
On macOS and Linux the app's Setup page installs it in one click; on Windows install
[Node.js](https://nodejs.org) first, then press Install. Setup also shows Claude, Codex and Gemini
and opens their sign-in.

## These builds are not signed

Nothing here is signed with a paid developer certificate, so each system warns the first time:

- **Windows:** in "Windows protected your PC", press **More info**, then **Run anyway**.
- **macOS:** open Botyard once, then **System Settings → Privacy & Security → Open Anyway**. Or in
  Terminal: `xattr -dr com.apple.quarantine /Applications/Botyard.app`
- **Linux AppImage:** `chmod +x Botyard-2.10.1-linux-x86_64.AppImage`, then run it.
- **Android:** allow your browser or file manager to install unknown apps when it asks. The APK is
  signed with the Android project's public test key, the same in every release, so a newer one
  installs over an older one. It is not from a store.

## What is new

- **2.10.1:** the desktop app starts again. In 2.10.0 it stopped as it started ("Botyard did not
  start") because the installer left out a file the map needs; a test now checks that every file
  Botyard loads is in the app. When Botyard cannot start, the reason is now written to its log
  (it was empty).

**Easier for a first yard**

- **OpenCode in one click on macOS and Linux.** With no Node.js on the computer, Setup's Install
  button uses OpenCode's own installer. Botyard finds it at once, without a restart.
- **Free keys, two steps in sight.** Each free provider on Setup (OpenRouter, NVIDIA, Google Gemini,
  Mistral, SambaNova, Cohere) has a **Get a free key** button beside the box to paste it. Pollinations
  needs no key at all.
- **A bot says why it cannot answer.** When no free model answers (the day's free allowance is used
  up, or every model is busy), the chat says so in ten seconds and tells you what to do. Before,
  it showed "Writing an answer" for half an hour.
- **Getting started rewritten for beginners:** what to install on Windows, macOS and Linux, and how
  to add free keys. See [Getting started](https://github.com/Venutian/botyard/blob/main/docs/getting-started.md).

**Free models**

- Free models are tried best first, by their published coding benchmark grade (SWE-bench Verified),
  and each one shows the Claude model it is about as good as.
- A bot that asks takes the strongest free model that answers, by the crew's measured pass rate.
- A provider that says "too many requests" rests for ten minutes while the run goes on, in the same
  session, on another provider's model.
- A run that ends without doing anything, or outgrows a model's context window, starts again on
  another model.
- Runs are booked on the model they really ran on, with their own cost and tokens.
- More free providers in one file: Google Gemini, Mistral, SambaNova and Cohere keys, and
  Pollinations with no key.

**A steadier crew**

- **Prepare release:** one click starts a product's release. The crew builds it, writes the store
  listing, makes and scores the store images, finds what a store would refuse, and waits for your yes.
- **Launch page:** every product on every store and channel, with its next step and who it waits on.
- **Running now:** what each bot's run and each helper is running on this computer, and leftover
  programs from ended runs are stopped.
- Work the public will see is scored before it lands, and no brief can skip that.
- A job whose runs keep ending well while leaving nothing is stopped with a reason instead of being
  run again.
- Main checkouts stay on main: bots work in their jobs' own folders, and a drifted checkout is put back.
- Bots commit only as the studio's own GitHub no-reply address.
- PC load control works on narrow screens, with larger touch targets.
- Engram's zoom keeps titles and excerpts on screen.
- **Phone app 1.14.0:** one card per bot, and the ruler's reasons shown on ideas.
